# Sprint 003 — Routing Hardening + Staged Construction

**Status:** Planned. Full specification in [architecture/action-routing-hardening.md](../architecture/action-routing-hardening.md). Rationale in DR-0020.

**Goal:** Remove the recurring cross-module matching defect at its root (category-scoped routing), and give sited multi-stage structures somewhere to exist. Both are foundation-hardening required before the three AIs are wired, because a misrouted action both wastes the AI call routing was meant to save and corrupts the data the Auditor must then validate.

**Baseline fixture:** the 15 m² cabin simulation routes 0 of 12 steps to COVERED today. That number is the measure this sprint must move.

### M1 — Category vocabulary and the classifier
- [ ] `activity_category` + `category_term` tables, seeded from existing intent keywords
- [ ] `ActivityClassifier.classify(text)` — deterministic, cached, no API cost
- [ ] Ambiguity handling with contest recording
- [ ] Unit tests for all four recorded collisions + the ambiguous verb pairs (dress, fire, plant, draw)
- [ ] Auditor invariant: no term in >3 categories without a reason

### M2 — Scoped resolution
- [ ] Category columns on material_process, technique_definition, construction_kind, fire_method, mineral_definition, flora_definition (backfilled)
- [ ] ArchitectRouter, runProcess, and intent classification all filter by category
- [ ] Auditor invariant: every matchable row has ≥1 category (same migration as columns)
- [ ] Regression: the four collisions, no false cabin coverage

### M3 — Staged construction
- [ ] construction_stage + construction_stage_requirement + construction_progress
- [ ] Stage dependency enforcement; ADVANCE_CONSTRUCTION intent; per-stage narration
- [ ] Auditor invariants: no orphan/cyclic stages, no unobtainable stage requirement
- [ ] Migrate LEAN_TO and STONE_FIRE_PIT onto stages with no behaviour change

### M4 — Building vocabulary
- [ ] Framing members, joinery, foundation, building layers, timber preservation
- [ ] Each passes the V53 review gate; reachability stays at zero unreachable

### M5 — Coverage as a standing measure
- [ ] Per-category coverage on /api/domains/coverage
- [ ] INVENT assessments recorded as ranked gap rows
- [ ] Cabin simulation harness as a build-time regression fixture

**Definition of done:** no matcher queries its vocabulary without a category filter; the cabin routes to COVERED/POLISH on all twelve steps; a coverage regression fails the build.
