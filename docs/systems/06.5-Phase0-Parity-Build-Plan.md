## Context — what today's review established

A live playthrough (Chronicle 9, "Wolf Kingdom", Days 1–10) was run in **Phase 0** — a single ChatGPT acting
as the whole engine over 13 hand-saved JSON files — and felt **richer and less restrictive** than the current
**Phase 1** deterministic engine, despite Phase 1 having a superior UI, real persistence, real physics, and no
hallucinated matter. The review of that database + the new GitHub issues (#29–#37) produced **DR-0022**. The
short version: Phase 1 is *sounder but thinner*, and the thinness is fixable **additively**, not by a rewrite.

### Why Phase 0 felt richer (and the corrected reading)
- It said **yes** to any rational action (a "recipe" there is just a *name*; crafting was improvised).
- Every **object was thick** — capabilities, dimensions, provenance (`tools_used`), and a dated
  `modifications` log (the Utility Belt went Revision I→II→III, each adding a tool holder).
- **Corrected principle (user, 2026-08-04):** the goal is **NOT** Phase 0's fuzzy resource pools. Phase 1's
  **exact numerical quantities stay.** The missing piece is **AI reasoning** that says *yes, that's rational*
  and then does the bookkeeping precisely — templates as guides, Architect authors, Auditor validates,
  persistence is numerically accurate. See DR-0022 principles 1–4.
- **Reachability principle (user, 2026-08-04):** an action may use everything **physically in reach** —
  carried, on the ground nearby, **in on-site storage**, and **tools in a nearby rack** — not just carried
  load. One unified model. See DR-0022 principle 2.

## The plan (layered; deterministic first, AI-on after)

### Layer 1 — Unified reachability *(deterministic, key-free, DO FIRST)*
- [ ] One reachability model = carried + nested-in-carried + loose-at-location + **contents of containers/storage sited at the location/zone**, for **materials and tools**, each with **count + source**. Fixes F2/F3/F4 and the stone-shelf limitation.
- [ ] Route **every** input-sourcing (`hasAtLeast`, `hasAtLeastHere`, `consumeOne`, `consumeOneHere`, `reachableItemKeys`) and **tool checks** through it — no path may disagree.
- [ ] Scope to the current **zone** where sub-locations exist (V18/V34), else the chunk; a tool in a rack is reachable because you are at that workstation zone.
- [ ] Regression tests: pull a material from an on-site bin; use a tool from an on-site rack; first-craft consumes a ground item.

### Layer 2 — Make perception reveal the world *(2a deterministic; 2b AI-enriched)*
- [ ] **2a** OBSERVE/TRACK/ANALYZE/INVESTIGATE name the *actual* present entities: flora (`chunk_flora`), wildlife (`wildlife_population`), fish/aquatic species, insects, stored materials, structures — scaled by mastery/attention. Fixes F5, #33, #37-sensory, and the "can't hunt what you can't see" complaint. Deterministic.
- [ ] **2b** *(AI-on)* deepest examination tier enriched by the Narrator, non-load-bearing.

### Layer 3 — Quantified, sourced AI context + templates as exemplars *(built on Layer 1)*
- [ ] Interpreter/Architect receive the **quantified, sourced** reachable pool (counts + where), not bare keys.
- [ ] Feed the **130 processes as exemplars** into the Interpreter/Architect prompts (the "templates as guides" of DR-0022 §3), so authored recipes look like real ones (proper inputs, tool, mass-balanced output).
- [ ] Miss path stops returning the ambiguous one-liner when the pipeline is available; engages Interpreter→Architect.

### Layer 4 — Thick objects (additive attribute layer) *(deterministic schema; author fills it)*
- [ ] `V68` additive `object_attribute` (+ `object_modification`) on `world_object`: capabilities, purpose, dimensions, `tools_used`, classification flags, a dated modification log — **additive metadata, never touches mass balance**.
- [ ] The Architect populates these when authoring (a hand-carry basket **with a handle**, dimensions); REFINE appends to the modification log.
- [ ] Reading an object (grab/inspect) surfaces its attributes with accurate **numerical** state.

### Layer 5 — Richer narration templates (#30)
- [ ] Rework base templates into a multi-block, 3–5 sentence frame (Progression / Observation / …) built on the existing `PerceptionFrame` + `StateChange` deltas; lowers AI-narrator cost.

### Quick fixes (small, independent)
- [ ] **#32** add `bath`/`bathe`/`take a bath` to WASH; accept `RIVER_BANK` (and water-adjacent) for WASH/DRINK, not only `WETLAND`.
- [ ] **#36** classifier: "craft/weave a fishing **net**" must not match the FISH intent.
- [ ] **#31** `CRAFT_BASKET` must not exclude "carry"/"hand-carry".

### Operator-gated (needs the key)
- [ ] Turn on `DRAUGR_AI_ENABLED` + `draugr.ai.authoring-enabled`; live-verify the basket example end-to-end (author → gate → QA → `chronicle_tech_discovery` → Auditor → persisted with exact counts → grab-able). Tune prompts.

## The canonical acceptance example (the basket)

> Reachable (carried + on-site bins/racks): `dry_branch ×5`, `plant_fiber ×5`, `fiber_cordage ×2`, `vine ×3`,
> stone knife in the on-site Tool Shed. Action: *"weave a hand-carry basket with a handle — cut and bend the
> branches to a frame, weave fibre and vine across it, tie the handle with cordage."*

1. **Layer 1** makes all of the above reachable (branches on the ground, cordage in the fibre bin, knife in the rack).
2. **Interpreter** tries existing recipes → `weave_large_basket` (8 fibre + 8 vine) doesn't fit; no "with handle" variant.
3. **Architect** authors `hand_carry_basket_handled` ← `dry_branch ×3 + plant_fiber ×4 + fiber_cordage ×1 + vine ×2`, tool CUTTING, output mass ≤ input mass; attributes `{handle:true, dimensions:…, capabilities:[carry]}`.
4. **Gate** (mass/reachability) → **QA** (plausibility, ≤2 rounds) → `chronicle_tech_discovery` → **Auditor** validates.
5. **Execute** consumes exactly those counts; the basket persists with accurate numerical data and is grab-able later.

When this round-trips with the key on, the thread's core goal is met.
